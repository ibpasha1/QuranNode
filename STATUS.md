# QuranNode — build status

A distraction-free Quran reader/player device (ESP32-S3, 3.5" ST7796S in **portrait
320×480**, PCM5102 DAC, INMP441 mic, SD, capacitive touch, 5-way switch). Built
**simulator-first**: the portable core (`core/`) runs today in an SDL desktop
window and later compiles unchanged to ESP32-S3 firmware. Full plan:
`~/.claude/plans/mossy-pondering-crab.md`.

## Architecture

```
core/     portable C99 (no platform headers)   — gfx, arabic, quran, audio, scenes, app
hal/      the platform seam (hal.h)             — sim/ (SDL2), esp32/ (M2, ESP-IDF)
sim/      desktop harness (SDL loop)
tools/    offline Arabic pipeline (HarfBuzz+FreeType) + venv
assets/   generated glyph packs + preview/verification images
sdcard/   local mirror of the on-device /sdcard (packs/, audio/, quran/)
```

Platform I/O only ever happens behind `hal.h`. The core never calls SDL or ESP-IDF.

## Build & run

```sh
# one-time: simulator + pipeline deps
brew install sdl2 pkg-config sound-touch
python3 -m venv tools/.venv && tools/.venv/bin/pip install uharfbuzz freetype-py pillow

# generate the Arabic glyph pack (Al-Fatiha sample for now)
tools/.venv/bin/python tools/shape_quran.py --preview assets/preview
# fetch + slice per-ayah recitation and word timings (needs ffmpeg)
tools/.venv/bin/python tools/fetch_sample.py

make run          # build + open the SDL simulator window
make dump && ./quran-dump out.ppm ">>>>"   # headless: render a frame (no window)
```

Sim keys: arrows = navigate, Enter = select, Space = play/pause, `,`/`.` or mouse
wheel = rotary encoder, `R`/click = encoder press, Backspace/`B` = back, `M` = menu.

## Milestones

- [x] **M0 — skeleton + Arabic proof.** Portable gfx core (canvas/theme/font from
      DSP-Mini, de-esp-ified), SDL HAL, scene state machine, and the offline
      HarfBuzz→glyph-pack pipeline. The focus reader renders shaped Quranic Arabic
      (RTL, joining, tashkeel) with per-word boxes on the real device code path.
      Verified: `assets/preview/frame_reader_1_1.png`, `frame_reader_1_5.png`.
- [x] **M1a** — focus reader + recitation. Per-ayah recitation (dr_mp3 decode +
      SoundTouch pitch-preserving speed) synced to a live **word-by-word highlight**;
      multi-line ayah wrapping; encoder = speed while playing / ayah nav while paused;
      press = play/pause; auto-advance between ayat; position bar + reciter/speed footer.
      Audio + timings both sourced from Quran.com's Abdul Basit (Murattal) so they can't
      drift. Verified headless: `assets/preview/hl_1_1_c.png` (word 3 highlit @2.0s),
      `hl_1_7_w5.png` (line-2 word highlit). Hear it: `make run`.
- [x] **M1b** — Ayah Loop. Editor scene (from ayah → to ayah, each ×N, whole range ×M
      or ∞, pause between, speed) + a loop state machine in the Player: repeats each ayah,
      then the section, with inter-clip pauses, then stops. Reader shows a live loop-progress
      footer and keeps word-highlight running. Reached via the reader's MODE key. Verified:
      `make loop-test` (asserts exact play counts), `assets/preview/loop_editor.png`,
      `loop_active.png`. Saved named routines deferred to M1c (needs settings store).
- [x] **M1c** — Navigation + resume. Real `quran_db` (all 114 surahs + 30 juz, generated by
      `tools/build_db.py`); a jump nav scene (By Surah / By Juz / Bookmarks — surahs without
      bundled content shown dimmed); a HAL state store (`hal_state_*`) backing **one-press
      resume** (exact surah:ayah + speed, persists across runs) and bookmarks (reader K, with a
      ★ marker + toast). Also fixed a shaper bug where HarfBuzz code-point clusters were mapped
      as UTF-8 byte offsets, dropping the last word's highlight box. Verified:
      `assets/preview/nav_surah.png`, `resume_run2.png`, `hl2_sweep.png` (clean 4-word sweep).
- [x] **M1d** — Library. The MP3-player personality: a file browser over
      `sdcard/audio/library/**` (folders + tracks) and a Now-Playing view (progress,
      play/pause, speed, prev/next track, auto-advance) reusing the same audio HAL.
      Reached from Home (left). Verified: `assets/preview/lib_root.png`, `lib_playing.png`.
      (Sample tracks are placeholder copies of the sample ayat — swap in real audio later.)
- [~] **M2** — ESP32-S3 firmware, on the DSP-Mini DevKitC-1 + ST7796S (`devkit_st7796s`).
  - [x] **Phase 1** — firmware builds + links (`firmware/`, PlatformIO+ESP-IDF). `hal/esp32`
        binds the portable core to the real panel (native 480×320 — the reused ST7796S
        driver's upscale collapses to identity at our canvas size), the 5-way switch, and
        the microSD card (FAT `/sdcard`); resume/bookmarks persist to `/sdcard/state`.
        One `qn` IDF component globs core + hal/esp32 + copied DSP-Mini drivers.
        Flash: `cd firmware && pio run -e devkit_st7796s -t upload` (see `firmware/README.md`).
        **Not yet hardware-verified** (needs flashing on the board). Audio stubbed.
  - [x] **Phase 2 (M2-3)** — audio builds: MP3→I2S recitation. `hal/esp32/audio_esp32.c`
        decodes each ayah (minimp3) to 44.1kHz stereo PCM in PSRAM and streams it to the
        MAX98357A via I2S; the reader's word-highlight follows the playhead. Serial-monitor
        keyboard control (both UART0 + USB-Serial-JTAG). **Al-Fatihah bundled in flash**
        (glyph pack + timings + 7 MP3s as C arrays, `tools/gen_embedded.py`) so reader +
        audio work with **no SD card**. Flash 1.4MB. Speed/time-stretch on device: TODO.
        **Not yet hardware-verified for audio** (display + input confirmed working on board).
  - [x] **Custom board pinout** — migrated from the borrowed DSP-Mini rig to the custom
        prototype (`hardware/prototype/PINOUT.md`): PCM5102 I2S out on 4/5/6, PAM8302
        speaker-amp enable on GPIO18 (`PIN_AMP_EN`, replaces the MAX98357 SD pin — headphones
        run off the DAC's line-out jack, the amp toggle = speaker on/off), SD→SPI3 1/2/42/41,
        5-way switch→40/39/38/47/21 (real DOWN → clean up/down/left/right/center + hold=back),
        touch I2C 16/17 and mic 7/8/9 reserved for their drivers. Display unchanged (10–15).
        `pin_config.h` rewritten; builds clean (Flash 63%).
- [x] **Settings** — real preferences scene (reached via nav ▸ Settings): recitation
      speed, Arabic font size (Small/Medium/Large/**Extra Large**/**Huge** — five pre-baked
      glyph packs the reader hot-swaps; at XL/XXL the reader drops the prev/next context to
      make room), screen brightness (LEDC on device, dims the sim preview), and a tajweed
      toggle. Persisted via `hal_state` (`core/quran/prefs.[ch]`), applied at boot. Verified:
      `assets/preview/settings.png`, `font_compare.png`, `reader_xxl.png`.
      (Makefile now does `-MMD` header-dependency tracking; app partition raised to 10 MB
      and embedded assets split into per-file `emb_*.c` to hold the 10 packs.)
- [x] **Tajweed rule colors** — authoritative rule classification (cpfair/quran-tajweed, Hafs)
      baked offline into colored glyph packs: the shaper writes a per-pixel rule-color plane
      (`tools/shape_quran.py --tajweed`), the device renders it via `arabic_draw_ayah_colored`
      + a fixed palette (red=necessary madd, amber=madd, green=nasal, blue=qalqala, grey=silent),
      and the reader loads the `_tj` pack when the Settings toggle is on. Verified:
      `assets/preview/reader_tj_7.png` (red madd laazim in ٱلضَّآلِّينَ). 6 packs bundled in flash.
- [ ] **Beyond** — WiFi companion, tafsir/prayer, content expansion

**Scene map:** Home → Reader (focus/recitation) · Loop (ayah loop, MODE from reader) ·
Nav (surah/juz/bookmarks, MENU/→ from home) · Library (local audio, ← from home) · Settings (stub).

## Known rough edges (deferred)

  multi-line wrapping lands in M1a.
- `hal_audio_*` are stubs until M1a.
- Word boxes for adjacent short words can visually merge (cosmetic).
- Surah names are a 3-entry stub until `quran_db` (M1c).
